二、合规判断一：业务模式决定是否需要ICP许可证<img width="1690" height="816" alt="25fba1fb617bf0acb4b0a7741318867c" src="https://github.com/user-attachments/assets/c9b6fba2-9372-4447-ba5e-80d32513280d" />

这是外卖订餐系统最容易被误判的合规问题。“依托微信小程序运营就无需ICP许可证”这一说法有严格的前提条件。

根据工信部政策，企业依托微信、支付宝等互联网平台的小程序、公众号等形式经营业务，且无其他独立运营平台的，无需取得增值电信业务经营许可证。广东省通信管理局的官方答复也明确：“企业依托微信、支付宝等互联网平台的小程序、公众号或依托智能终端设备的应用程序等形式运营，且无其他独立运营平台的，无需取得《增值电信业务经营许可证》。”

但这个豁免有两个关键限制：

第一，“无其他独立运营平台”是硬性前提。 如果你的外卖系统除了微信小程序之外，还计划开通独立的H5网站、APP或PC端管理后台对外运营，就不再满足豁免条件。

第二，业务模式决定“自营”还是“平台”。 工信部政策明![Uploading 2025042311183073.png…]()
确：企业以自营方式直接销售自身或其它企业的商品或服务，无其他单位或个人以自身名义入驻实施销售行为的，无需办理ICP许可证。如果你的外卖系统是自营餐厅（只有你自己一家店，用户下单后由你配送），豁免成立。但如果系统允许多个商家入驻、每个商家以自身名义销售菜品、平台提供交易撮合并可能抽成，业务实质属于“为他人提供平台服务”。行业分析指出，“电商平台类：若允许第三方商家入驻，则需要EDI许可证（在线数据处理与交易处理业务）和ICP许可证”，外卖平台被归类为“100%需要提供ICP许可证”的类目。

务实的判断标准： 打开你的系统，看看是否有“商家入驻”功能。如果有，且入驻商家以自身品牌对外经营，ICP许可证大概率绕不开。

三、合规判断二：食品安全备案是法定义务
无论是否豁免ICP许可证，网络餐饮服务提供者都必须完成食品安全备案。

《网络餐饮服务食品安全监督管理办法》第五条规定了两种备案义务：

网络餐饮服务第三方平台提供者（即允许多商家入驻的平台方）：应当在通信主管部门批准后 30个工作日内，向所在地省级市场监督管理部门备案。
![Uploading 2025042311183560.png…]()

自建网站餐饮服务提供者（即自营外卖系统、通过自己的小程序或网站提供餐饮服务）：应当在通信主管部门备案后30个工作日内，向所在地县级市场监督管理部门备案。

未履行备案义务的后果： 由县级以上市场监督管理部门责令改正，给予警告；拒不改正的，处5000元以上3万元以下罚款。

这意味着，即使你的自营外卖小程序豁免了ICP许可证，ICP备案（2023年7月起所有小程序均需完成）之后，还有一道食品安全备案必须完成。 顺序不能颠倒：先通信主管部门备案（ICP备案），再凭备案号到市场监管部门完成餐饮服务备案。

四、合规判断三：扫码点餐的个人信息保护是执法重点
如果你的系统同时包含“店内扫码点餐”功能（用户到店后扫桌码点餐），需要特别注意——扫码点餐是2025-2026年个人信息保护执法的高频领域。

全国网络安全标准化技术委员会发布的《网络安全标准实践指南——扫码点餐个人信息保护要求（征求意见稿）》明确了三条核心禁令：

禁止强制收集非必要信息。 手机号、位置信息、平台账号信息均不属于扫码点餐的必要信息。指南明确：“不得通过强制关注公众号、注册会员等误导、欺诈、胁迫等方式处理个人信息。”

禁止强制关注公众号或注册会员。 江苏丹阳检察院办理的案件中，餐饮商家因“必须授权商家获取手机号、昵称、位置等个人信息后才能继续点餐”被认定违规，经检察建议督促后整改为“消费者点餐不再获取个人信息”。长沙望城区检察院的调查也发现，“扫码点餐容易，想要注销授权却连操作入口都找不到”，推动商家在会员页面提供注销端口。

必须提供账号注销途径。 实践指南要求：提供账号注册功能收集个人信息的，必须提供有效的注销账号途径；用户注销的，应及时删除或匿名化处理其个人信息。

执法案例的警示： 太原万柏林公安网安部门查处的案例中，某餐饮“咖啡点餐”小程序“隐私政策藏得极深，在正常点餐操作路径中几乎找不到入口”，被依法责令改正并予以警告。山西警方明确提醒：“个人信息保护、数据安全管理、网络等级保护是法定必尽义务，绝非锦上添花。”

对你的系统的直接影响： 如果源码默认要求手机号登录才能点餐、或强制关注公众号后才能进入菜单，上线后即构成违规。购买源码时需要确认：是否支持游客模式点餐（无需任何个人信息即可浏览菜单和下单）、隐私政策弹窗是否可配置、是否有账号注销入口。

五、购买源码前的合规自查清单
业务模式层面： 系统是自营（只有你自己的店）还是多商家入驻平台？后者需要评估ICP许可证和食品安全平台备案。

ICP备案层面： 小程序是否已完成ICP备案？（2023年7月起所有小程序均需完成，否则不得上架）

食品安全备案层面： 自营模式需向县级市场监管部门备案，平台模式需向省级市场监管部门备案。

扫码点餐合规层面： 用户扫码后是否可直接浏览菜单和下单，无需提供手机号或关注公众号？隐私政策是否以弹窗形式展示且支持主动勾选？是否有账号注销入口？

源码授权层面： 开源项目（如苍穹外卖）可用于学习参考，但商用需确认授权条款。bee-api 项目明确“商用请联系作者授权”。

结语：源码解决的是“能不能跑”，合规解决的是“能不能活”
一套外卖订餐小程序的源码和文档，技术上足以支撑功能演示或课程设计。但从“跑通”到“上线运营”，中间隔着ICP备案、食品安全备案、扫码点餐个人信息保护改造三道门槛。自营模式和多商家平台模式的合规成本相差数倍——前者可能只需完成备案，后者则需要ICP许可证和省级食品安全备案。

务实顺序是：先确认业务模式（自营还是平台），再匹配对应资质路径，然后检查源码是否支持合规所需的流程改造（游客模式点餐、隐私弹窗、账号注销），最后才谈功能扩展。
